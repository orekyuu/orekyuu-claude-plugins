# コードの解説の書き方

読者が、コードの役割と処理の仕組みを理解できる解説を書く。
共通の進め方は [作成の流れ](writing-flow.md) に従う。
文章は [執筆の指針](../SKILL.md) に沿って整える。

## 書く前に確認すること

- 読者が知りたい範囲と、必要な説明の深さを確認する。
- 対象のコードと、その呼び出し元を読む。
- 主要な依存先と、関連する設定を確認する。
- テストや仕様から、期待される振る舞いを確認する。
- 説明対象のブランチやリビジョンを把握する。

## 出力形式を選ぶ

- その場で理解するための解説は、コンソールに出力する。
- 保存や共有を目的とする解説は、Markdownレポートにする。
- ユーザーが形式や保存先を指定した場合は、それに従う。
- 指定がなければ、コンソールに出力する。

## 共通して説明する内容

抽象から具体へ、次の順序で解説する。
この順序は、コンソールとMarkdownレポートの両方に適用する。

### 1. 全体の役割と流れ

- 冒頭で、コードが何をするものかを説明する。
- システム内の役割と、呼び出される条件を示す。
- 入力、出力、主要な副作用を明示する。
- 入力から結果までの全体の流れを、大きな段階に分けて示す。

### 2. 主要な登場人物

- 主要なコンポーネント、クラス、関数を紹介する。
- 各登場人物の責務を説明する。
- 呼び出しやデータの受け渡しの関係を示す。
- 全体の流れの中で、それぞれが担う段階を対応付ける。

### 3. 具体的な実装と処理の流れ

- 入口から結果が返るまでを、実行順に説明する。
- 全体の各段階を、実際の実装に対応付ける。
- 読者の疑問に関係する処理に絞る。
- 主要な関数や型を、実際の名前で示す。
- 分岐条件と、分岐後の振る舞いを対応付ける。
- 例外処理や境界条件は、理解に必要な範囲で説明する。
- 必要に応じて、具体的な入力例と結果を示す。

### 根拠と設計意図

- 説明した処理に、ファイルやシンボルの参照を添える。
- 行番号を記載する場合は、対象のコードで確認する。
- コードから分かる動作と、設計意図を区別する。
- 意図を説明する場合は、コメントやADRなどの根拠を確認する。
- 根拠がない設計意図は、推測としても説明に含めない。
- 静的な読み取りと、実行して確認した結果を区別する。

## コンソールに出力する場合

冒頭で質問への回答と全体の流れを短く伝える。
主要な登場人物を紹介してから、具体的な実装へ進む。
スクロールしながら、要点を追える長さと構成にする。

### 書き方

- 質問された範囲を中心に説明する。
- 冒頭で、役割や仕組みの要点を短く伝える。
- 処理の流れは、短い段落や番号付きリストで示す。
- 関連するファイルやシンボルを、説明の近くに示す。
- コードの引用は、理解に必要な部分に絞る。
- 狭い表示幅でも読めるよう、横に長い表を避ける。
- 特定の関数の質問では、システム全体の説明を広げすぎない。

### 構成例

短い質問では、見出しを使わずに説明してもよい。

```text
対象の役割と、質問への回答を短く書く。

全体の流れ
入力から結果までを、大きな段階に分けて示す。

主要な登場人物
各コンポーネントの責務と、相互の関係を示す。

具体的な実装と処理の流れ
1. 入力を受け取る箇所を示す。
2. 主な処理と分岐を説明する。
3. 結果と、その返し方を説明する。

関連するコードの参照と、必要な注意点を添える。
```

## Markdownレポートに書き出す場合

会話を読んでいない人にも、単独で理解できる文書にする。
後からコードと照合できるよう、対象と参照先を明記する。

### 書き方

- タイトルに、解説する対象と目的を含める。
- 対象読者と、解説する範囲を明示する。
- 対象のリポジトリと、確認したリビジョンを記録する。
- 全体の流れ、主要な登場人物、具体的な実装を順に説明する。
- ファイルへのリンクは、保存先や共有先からたどれる形にする。
- コードを引用する場合は、出典と対応する処理を示す。
- 説明に関わる制約は、根拠を確認して記録する。
- 未確認の点は、本文と分けて確認事項として記録する。

### 保存と完了報告

- 保存先が指定されている場合は、そのパスに書き出す。
- 指定がなければ、リポジトリの文書配置に合わせて決める。
- 書き出した後は、保存先へのリンクと要点を短く伝える。

### 構成例

対象の規模に応じて、必要な項目を選ぶ。

```markdown
# 対象のコードと解説の目的

## 対象と範囲

対象読者、対象リポジトリ、確認したリビジョンを書く。
解説する範囲と、前提知識を示す。

## 全体の役割と流れ

コードの目的と、システム内での位置付けを書く。
入力から結果までの全体の流れを示す。
入力、出力、主要な状態の変化を書く。

## 主要な登場人物

主要なコンポーネントの責務と、相互の関係を書く。
全体の流れの中で、各コンポーネントが担う段階を示す。

## 具体的な実装と処理の流れ

1. 入口で受け取る情報を書く。
2. 主な処理と分岐を書く。
3. 結果と、その返し方を書く。

## 設計上の理由と注意点

根拠のある設計意図と、関連する制約を書く。

## 参照先

関連するコード、仕様、ADRへのリンクを記載する。
```
