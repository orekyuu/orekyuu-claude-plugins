# 技術文書の書き方

読者が内容を理解し、必要な行動を取れる文書を書く。
既存の文書を推敲するときも、以下の指針を使う。

## 作成の進め方

作成時は [ドキュメント作成の流れ](docs/writing-flow.md) を読む。
情報収集、構造化、出力の順に進める。
指定のフォーマットがある場合は、その形式に合わせる。

### 用途別の書き方

作成する文書に対応するガイドを読む。

- [PRの概要](docs/pull-request.md)：変更の目的、内容、影響を伝える。
- [コードの解説](docs/code-explanation.md)：処理の仕組みと根拠を伝える。

## 読者と目的

- 対象読者と、その知識レベルを明確にする。
- 読者に理解してほしい内容を決める。
- 読後に期待する行動を明確にする。
- タイトルに文書の目的と検索用のキーワードを含める。

## 文の書き方

### 一文を短くする

- 一文には一つの意味を持たせる。
- 一文は50文字以内に収める。
- 「〜だが」「〜ので」で複数の情報をつながない。
- 重要な情報を先に書き、理由や補足は別の文にする。

### 必要な情報を明確にする

- 5W1Hを意識し、理解や行動に必要な情報を明示する。
- 簡潔にするために、必要な情報を削らない。
- 修飾語は、修飾する対象の近くに置く。
- 二重否定を避ける。
- 読者が行う操作は能動態で書く。
  - 例：「設定ファイルを保存してください。」
- 操作の結果は受動態で書く。
  - 例：「設定が保存されます。」
- 「など」を使う場合は、列挙した対象の種類を明示する。
  - 例：「AやBなどのソフトを使用してください。」
  - 対象がAとBだけなら「AやBを使用してください。」と書く。

### 冗長な表現を省く

- 同じ説明を繰り返さない。
- 文書の目的に関係しない情報を書かない。
- 接続詞は、文の関係を示すために必要な箇所だけに使う。

## 文書の構造

- 情報を意味のまとまりごとに分ける。
- 見出しと空行で、まとまりの境界を示す。
- 並列の情報は箇条書きにする。
- 情報に親子関係がある場合は、箇条書きを階層化する。
- 箇条書きには、内容が分かる見出しを付ける。
- 一つの箇条書きは、原則7項目までにする。
  - 超える場合は、内容ごとにグループを分ける。

## 推敲

- 読者が理解し、行動するための情報がそろっているか確認する。
- 一文一義と50文字以内の基準で、長い文を分割する。
- 重複した説明や不要な接続詞を削る。
- 見出しと箇条書きが、情報の関係を表しているか確認する。
